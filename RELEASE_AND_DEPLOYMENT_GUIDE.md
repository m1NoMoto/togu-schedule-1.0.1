## 1. Инструкция по локальному запуску проекта

### Требования к окружению
* **Node.js**: версия `20.x LTS` или `22.x LTS`
* **npm**: версия `10.x` и выше

### Шаги запуска
1. **Распакуйте проект и установите зависимости**:
   ```bash
   cd togu-schedule
   npm install
   ```
2. **Создайте файл локальных настроек**:
   ```bash
   cp .env.example .env
   ```
3. **Запустите серверный прокси-шлюз ТОГУ** (в первом терминале):
   ```bash
   npm run server
   ```
   Шлюз запустится на `http://localhost:3001` (проверка состояния: `http://localhost:3001/api/togu/health`).
4. **Запустите клиентское приложение Vite** (во втором терминале):
   ```bash
   npm run dev
   ```
   Откройте в браузере адрес `http://localhost:5173`.
5. **Запустите автоматические тесты** (для проверки всех модулей):
   ```bash
   npm test
   ```

## 2. Инструкция по развёртыванию сервера и базы данных

### 2.1. Развёртывание базы данных (PostgreSQL / Supabase)
1. Создайте новый проект в **Supabase** (или поднимите экземпляр PostgreSQL 15+).
2. Откройте **SQL Editor** и выполните скрипт миграции из файла:
   ```text
   supabase/migrations/001_togu_schedule_schema.sql
   ```
3. Скрипт автоматически создаст:
   * Реляционные таблицы без дублирования: `study_groups`, `subjects`, `teachers`, `classrooms`, `schedule_slots`, `schedule_overrides`, `calendar_events`, `sync_logs`.
   * Изолированную таблицу пользовательских настроек `user_preferences` (привязка к анонимному `device_anon_id` без обязательной регистрации).
   * Уникальные индексы `ux_schedule_slots_natural` для идемпотентного обновления (`ON CONFLICT DO UPDATE`).
   * Политики **Row Level Security (RLS)**: публичное чтение (`SELECT`) расписания для всех студентов и запрет изменения общих таблиц с клиентских ключей (запись разрешена только сервисному воркеру синхронизации).

### 2.2. Развёртывание серверного шлюза (`server/toguServer.mjs`)
Серверный шлюз выполняет роль кэширующего прокси между приложением и сайтом `https://togudv.ru/rasp/groups/`, обходя браузерные ограничения CORS и защищая сервер вуза от перегрузки.

**Вариант А — Запуск через PM2 на VPS (Ubuntu / Debian)**:
```bash
npm install -g pm2
TOGU_SERVER_PORT=3001 CORS_ALLOWED_ORIGIN=https://your-domain.ru pm2 start server/toguServer.mjs --name togu-proxy
pm2 save
pm2 startup
```

**Вариант Б — Конфигурация обратного прокси Nginx (HTTPS)**:
```nginx
server {
    listen 443 ssl http2;
    server_name rasp-app.your-domain.ru;

    location /api/togu/ {
        proxy_pass http://127.0.0.1:3001/api/togu/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }

    location / {
        root /var/www/togu-schedule/dist;
        try_files $uri $uri/ /index.html;
    }
}
```

## 3. Инструкция по сборке мобильного приложения (Android APK / AAB)

### Способ 1. Облачная сборка в 1 клик через GitHub Actions (без установки Android Studio)
В проект уже встроен готовый workflow `.github/workflows/build-android-apk.yml` (настроенный на **Java JDK 21**, **Node.js 22** и предустановленный Android SDK):
1. Загрузите код проекта в репозиторий GitHub.
2. Перейдите во вкладку **Actions** → выберите workflow **Build TOGU Schedule Android APK**.
3. После завершения сборки (зелёная галочка) откройте сводку (**Summary**) и в блоке **Artifacts** скачайте архив **`togu-schedule-android-apk`**, внутри которого находится готовый установочный файл **`app-debug.apk`**.

### Способ 2. Локальная сборка на компьютере (Windows / macOS / Linux)
1. Убедитесь, что установлены **JDK 21** и **Android SDK** (Android Studio).
2. Выполните сборку веб-бандла и синхронизацию Capacitor:
   ```bash
   npm install @capacitor/core @capacitor/android @capacitor/local-notifications
   npm install -D @capacitor/cli
   npx vite build
   npx cap sync android
   ```
3. Соберите APK через Gradle:
   * **Linux / macOS**:
     ```bash
     cd android && ./gradlew assembleDebug --no-daemon
     ```
   * **Windows**:
     ```bat
     cd android && gradlew.bat assembleDebug --no-daemon
     ```
4. Готовый файл будет расположен по пути:
   `android/app/build/outputs/apk/debug/app-debug.apk`.
5. Для сборки подписанного релизного пакета **AAB / APK** для публикации в RuStore или Google Play:
   ```bash
   cd android && ./gradlew bundleRelease
   ```

## 4. Перечень необходимых ключей и настроек (без публикации секретов)

Шаблон всех переменных находится в файле `.env.example`. В репозитории и клиентском бандле секретные ключи отсутствуют.

| Переменная | Где используется | Назначение | Уровень секретности |
| :--- | :--- | :--- | :--- |
| `TOGU_SERVER_PORT` | Сервер (`toguServer.mjs`) | Порт HTTP-шлюза (по умолчанию `3001`) | Публичная конфигурация |
| `TOGU_BASE_URL` | Сервер (`toguServer.mjs`) | Базовый URL источника (`https://togudv.ru`) | Публичная конфигурация |
| `TOGU_CACHE_TTL_MS` | Сервер (`toguServer.mjs`) | Время жизни серверного кэша (по умолчанию `1800000` мс = 30 мин) | Публичная конфигурация |
| `TOGU_RATE_LIMIT_MS` | Сервер (`toguServer.mjs`) | Минимальный интервал между запросами к сайту вуза (`2500` мс) | Публичная конфигурация |
| `CORS_ALLOWED_ORIGIN` | Сервер (`toguServer.mjs`) | Разрешённый домен клиентского приложения для CORS | Публичная конфигурация |
| `VITE_API_BASE_URL` | Клиент (`Vite`) | URL серверного шлюза API (`/api/togu`) | Публичная (префикс `VITE_`) |
| `SUPABASE_URL` | Сервер / Клиент | URL проекта Supabase PostgreSQL | Публичная конфигурация |
| `SUPABASE_ANON_KEY` | Клиент (Чтение БД) | Анонимный ключ Supabase (ограничен RLS только на `SELECT`) | Публичный ключ чтения |
| `SUPABASE_SERVICE_ROLE_KEY` | **Только сервер** | Ключ записи в таблицы расписания при синхронизации | **СТРОГО СЕКРЕТНО** (не передавать на клиент) |
| `ANDROID_KEYSTORE_PASSWORD` | **Только CI/CD Secrets** | Пароль хранилища ключей `.jks` для подписи релизного APK/AAB | **СТРОГО СЕКРЕТНО** (хранить в GitHub Secrets) |

## 5. Перечень известных ограничений

1. **Отсутствие push-событий в реальном времени со стороны сайта ТОГУ**:
   * Официальный портал `togudv.ru/rasp/groups/` отдаёт только статические HTML-страницы и не имеет WebSocket/Webhook API. Поэтому обнаружение изменений происходит при плановой периодической проверке (каждые 30 минут днём и 4 часа ночью) либо при нажатии кнопки ручного обновления.
2. **Прямые запросы из браузера к `togudv.ru` блокируются CORS**:
   * Сайт университета не выставляет заголовок `Access-Control-Allow-Origin` для сторонних веб-доменов. В веб-версии для автоматической загрузки любых групп требуется запущенный прокси-шлюз `server/toguServer.mjs` (либо ручной импорт сохранённого `.html` файла).
3. **Зависимость от структуры HTML-разметки сайта ТОГУ**:
   * Парсер опирается на классы `.rasp-group-list`, `#all_weeks`, `table.rasp`, `.time-hour`, `#cal_week`. Если университет радикально изменит вёрстку сайта, парсер зафиксирует ошибку `SCHEMA_CHANGED_ERROR` в журнале синхронизации и сохранит последнюю рабочую версию расписания в локальной БД до обновления регулярных выражений.
4. **Ограничения энергосбережения OEM-оболочек Android (Xiaomi MIUI/HyperOS, Huawei EMUI, Samsung OneUI)**:
   * На некоторых смартфонах агрессивные алгоритмы экономии заряда могут задерживать фоновые будильники, если пользователь принудительно закрыл приложение смахиванием. Для бесперебойной работы карточки на экране блокировки рекомендуется отключить ограничение фоновой активности для приложения в настройках Android.
